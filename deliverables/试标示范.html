01 · 完整 User Prompt

请把当前仓库补成一个可恢复的公告增量采集程序。我们需要把两个分区的不稳定分页接口同步到 SQLite，避免采集进程中途退出后漏公告、重复落库或用旧版本覆盖更正信息。仓库 README 已给出源协议、固定数据最终状态和命令接口，请先阅读；只访问本机源，不接入真实网站。

这是功能开发任务。请一次完成实现、测试和运行说明，不需要向我确认技术方案。

一、实现 collector.py，严格提供 README 中的 run / status / reset 接口；Python 3.9+，仅用标准库。run 接受 --base-url、--db、--workers 与可选 --crash-before-commit。至少两个 worker 并发采集不同分区，每个分区内必须按游标顺序拉取，完成态要能持久化区分于初始态。HTTP 请求设有限超时；429 尊重 Retry-After，503/超时做有上限的指数退避，最多追加四次重试，耗尽或其他非成功响应应输出清楚错误并非零退出，不得虚报完成。

二、实现 README 约定的 announcements、quarantine、checkpoints 表和字段。按 (partition,id) 幂等合并，只让更高 revision 覆盖，支持墓碑删除且旧版本不能复活。严格校验记录；坏记录按分区、页游标、页内下标稳定隔离并保留原始 JSON 与原因，不影响同页其他合法记录。单页业务变更、隔离记录、下一游标必须在同一事务原子提交，处理好多线程 SQLite 锁竞争，不能跳过失败页。重跑已完成任务不得再次请求 /feed，业务和隔离数据不增加。

三、实现可验证的进程崩溃注入：--crash-before-commit north:n2 必须在该页全部 SQL 已执行、commit 之前 flush 指定日志，再 os._exit(86)。请不要用捕获异常模拟。去掉参数重启后从已提交游标恢复，最终数据等同干净首跑。不得通过清库重跑掩盖恢复错误。reset 只清指定采集库自己的数据，不动源状态、其他数据库或目录。

四、status 输出 README 约定的机器可读 JSON。请提供标准库 unittest 自动化测试，实际启动本地源，验证正常采集、429/503 处理、跨分区并发、重复和旧版覆盖保护、墓碑、坏记录隔离、完成后二次运行，以及子进程真实崩溃后的回滚与恢复。对重试耗尽等失败路径也提供测试，不要仅检查进程返回码或硬编码数字。

五、提供可在 Windows PowerShell 执行的演示步骤，干净启动到展示最终状态能在 90 秒内完成；输出足以核验数据库和源指标。不得修改 fixture_server.py 与 fixtures/pages.json，不得直接读取 fixtures 替代 HTTP，不得伪造成功日志。可以新增文件并补充 README 的运行说明。结束时列出实现文件、实际跑过的测试与结果，明确尚未验证的部分。
